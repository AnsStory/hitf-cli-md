Configuration & Setup ​

This page covers global configuration, project configuration, and IDE code snippet generation.

Global Configuration ​

hitf global-config generates a global config file for setting default translation services, API keys, etc.

Basic Command ​

sh
hitf global-config

The global config file is located in the user directory:

text
~/.hitf/config.json

Configuration Structure ​

json
{
  "translationSetting": {
    "translationService": "tencent",
    "servicePriority": ["tencent", "baidu", "openai", "google"],
    "services": {
      "tencent": {
        "secretId": "your_secret_id",
        "secretKey": "your_secret_key",
        "region": "ap-guangzhou"
      },
      "baidu": {
        "appId": "your_app_id",
        "secretKey": "your_secret_key"
      },
      "openai": {
        "apiKey": "your_api_key",
        "baseUrl": "https://api.openai.com",
        "model": "gpt-3.5-turbo"
      },
      "google": {
        "apiKey": "your_api_key"
      }
    }
  }
}

Priority ​

Global configuration serves as defaults; project configuration .hitf/setting.json overrides global configuration.

Project Configuration ​

hitf setting generates or opens the project-level configuration file.

Basic Command ​

sh
hitf setting

The configuration file is located at the project root:

text
.hitf/setting.json

Configuration Structure ​

json
{
  "$schema": "https://www.schemastore.org/hias-hitf.json",
  "translationSetting": {
    "locales": ["zh-CN", "en-US"],
    "outDir": ".hitf/lang",
    "i18nCallTemplate": "$t",
    "i18nImport": "import i18n from '@/i18n'",
    "translationService": "tencent",
    "servicePriority": ["tencent", "baidu", "openai", "google"],
    "services": {
      "tencent": { "secretId": "", "secretKey": "", "region": "ap-guangzhou" },
      "baidu": { "appId": "", "secretKey": "" },
      "openai": { "apiKey": "", "baseUrl": "https://api.openai.com", "model": "gpt-3.5-turbo" },
      "google": { "apiKey": "" }
    }
  }
}

Language Direction ​

Source language is determined by the first item in the locales array; the rest are target languages.

json
{
  "translationSetting": {
    "locales": ["zh-CN", "en-US", "ja-JP"]
  }
}

If your source code is English and you want to generate Chinese and Japanese:

json
{
  "translationSetting": {
    "locales": ["en-US", "zh-CN", "ja-JP"]
  }
}

Now the source language is en-US, and target languages automatically become zh-CN and ja-JP.

i18nCallTemplate Configuration ​

i18nCallTemplate supports string or array format, used to specify the i18n call function when replacing source code.

String format:

json
{
  "i18nCallTemplate": "$t"
}

Array format (supports multiple call styles):

json
{
  "i18nCallTemplate": ["$t", "t", "i18n"]
}

Supported call styles:

FormatExample
Simple function name$t, t, i18n
With parentheses templatei18n(), useI18n().t
Array["$t", "t", "i18n"]

The system automatically detects existing i18n calls in code to avoid duplicate wrapping.

i18nImport Configuration ​

i18nImport supports string or array format, used to automatically inject import statements during translation.

String format:

json
{
  "i18nImport": "import { useI18n } from 'vue-i18n'"
}

Array format (multi-line imports):

json
{
  "i18nImport": [
    "import { useI18n } from 'vue-i18n'",
    "const { t } = useI18n()"
  ]
}

Supported file types:

File TypeInjection Location
.vueAfter <script> tag
.js / .tsAfter last import statement / file top
.jsx / .tsxAfter last import statement / file top
.jsonNot injected

Smart merge features:

  • Automatically detects existing import statements to avoid duplicate injection
  • Supports partial import scenarios (e.g., only import without initialization code)
  • Empty array or empty string will not inject anything

Key Strategy ​

Default uses translated English to generate snake_case keys, with sequence numbers appended on collision:

json
{
  "translationSetting": {
    "keyStrategy": {
      "maxLength": 40,
      "collision": "number",
      "hashLength": 6
    }
  }
}

If you prefer stable key suffixes across multiple runs, switch to hash:

json
{
  "translationSetting": {
    "keyStrategy": {
      "collision": "hash"
    }
  }
}

Unused Key Cleanup ​

By default, existing keys in locale files are preserved to avoid deleting manually maintained historical translations. Enable only when you want to clean up unreferenced keys in the current namespace:

json
{
  "translationSetting": {
    "pruneUnusedKeys": true
  }
}

Multi-Project outDir Configuration ​

outDir supports string or object format. Object format is useful for monorepo setups:

String format (default):

json
{
  "translationSetting": {
    "outDir": ".hitf/lang"
  }
}

Object format (monorepo):

json
{
  "translationSetting": {
    "outDir": {
      "main": "apps/main/src/locale/module",
      "web": "apps/web/src/locale/module"
    }
  }
}

Use -p, --project to specify the project. Without it, the first key is used by default:

sh
# Default uses "main" (first key in the object)
hitf tf apps/main/src/views/index.vue home

# Specify project
hitf tf apps/main/src/views/index.vue -p main
hitf tf apps/web/src/views/index.vue home -p web

# tfo also supports -p
hitf tfo apps/main/src/views views -p main

Output Directory ​

Translation results are typically written to the locale module directory:

text
src\locale\module\demo
.hitf\locale\module\demo

Actual paths depend on your project configuration.

IDE Code Snippets ​

hitf codesnippets generates IDE code snippets for quickly inserting translation ignore comments.

Basic Command ​

sh
hitf codesnippets           # Auto-detect IDE (.vscode / .idea / .cursor)
hitf codesnippets vscode    # Generate VS Code snippets
hitf codesnippets webstorm  # Generate WebStorm templates
hitf codesnippets cursor    # Generate Cursor snippets
hitf codesnippets sublime   # Generate Sublime Text snippets

Auto Detection ​

The command automatically detects the IDE type in your workspace:

DirectoryDetection Result
.vscode/VS Code
.idea/WebStorm / IntelliJ
.cursor/Cursor
No matchDefault VS Code

Generated Snippets ​

PrefixPurpose
@hitf-i18n-ignore-nextIgnore next extractable segment
@hitf-i18n-ignore-startIgnore range start
@hitf-i18n-ignore-endIgnore range end
@hitf-i18n-ignore-fileIgnore entire file

Usage ​

VS Code / Cursor ​

  1. Run hitf codesnippets vscode
  2. Type @hitf-i18n-ignore-next in code
  3. Press Tab to expand

WebStorm ​

  1. Run hitf codesnippets webstorm
  2. View in Settings > Editor > Live Templates

Sublime Text ​

  1. Run hitf codesnippets sublime
  2. Type @hitf-i18n-ignore-next in code
  3. Press Tab to expand

Snippet Content ​

Each snippet includes bilingual descriptions, for example:

json
{
  "忽略下一段翻译": {
    "prefix": "@hitf-i18n-ignore-next",
    "body": ["// @hitf-i18n-ignore-next", "$1"],
    "description": "忽略下一段翻译 (Ignore next extractable segment)"
  }
}
