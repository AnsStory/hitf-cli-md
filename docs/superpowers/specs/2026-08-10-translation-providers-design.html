翻译功能设计

翻译提供商扩展设计文档 ​

概述 ​

本文档描述了为hias-cli添加谷歌翻译和GPT翻译支持的设计方案。通过创建翻译提供商抽象层，支持多种翻译服务，并实现故障转移机制。

目标 ​

  1. 添加谷歌翻译（Google Cloud Translation API）支持
  2. 添加GPT翻译（OpenAI API）支持
  3. 创建翻译提供商抽象层，便于未来扩展
  4. 实现故障转移机制，提高翻译可靠性
  5. 重构配置结构，支持多翻译服务配置

架构设计 ​

翻译提供商管理器 ​

翻译提供商管理器负责管理所有翻译提供商：

javascript
// lib/translation/providers/provider-manager.js
class ProviderManager {
  constructor() {
    this.providers = new Map();
  }

  /**
   * 注册翻译提供商
   * @param {string} name - 提供商名称
   * @param {TranslatorProvider} provider - 提供商实例
   */
  register(name, provider) {
    this.providers.set(name, provider);
  }

  /**
   * 获取翻译提供商
   * @param {string} name - 提供商名称
   * @returns {TranslatorProvider} 提供商实例
   */
  get(name) {
    return this.providers.get(name);
  }

  /**
   * 检查提供商是否已注册
   * @param {string} name - 提供商名称
   * @returns {boolean} 是否已注册
   */
  has(name) {
    return this.providers.has(name);
  }

  /**
   * 获取所有已注册的提供商名称
   * @returns {string[]} 提供商名称数组
   */
  getRegisteredProviders() {
    return Array.from(this.providers.keys());
  }
}

// 单例实例
const providerManager = new ProviderManager();
module.exports = providerManager;

配置字段说明 ​

  1. translationSetting.translationService - 当前使用的翻译服务（tencent/baidu/openai/google）
  2. translationSetting.servicePriority - 翻译服务优先级数组，按顺序尝试
  3. translationSetting.services - 各翻译服务的配置
    • openai - GPT翻译配置
      • apiKey - OpenAI API密钥（必填）
      • baseUrl - API端点（可选，默认为OpenAI官方端点）
      • model - 模型名称（可选，默认为gpt-3.5-turbo）
    • google - 谷歌翻译配置
      • apiKey - Google Cloud Translation API密钥（必填）
    • baidu - 百度翻译配置
      • appId - 百度翻译应用ID（必填）
      • secretKey - 百度翻译密钥（必填）
    • tencent - 腾讯翻译配置
      • secretId - 腾讯云密钥ID（必填）
      • secretKey - 腾讯云密钥（必填）
      • region - 区域（可选，默认为ap-guangzhou）

数据流 ​

翻译流程 ​

  1. 配置加载：从配置文件中读取translationSetting配置
  2. 翻译服务选择：根据translationService字段选择主翻译服务
  3. 翻译请求：
    • 如果主翻译服务配置完整，使用主翻译服务
    • 如果主翻译服务配置不完整或失败，根据servicePriority顺序尝试其他翻译服务
  4. 翻译执行：调用对应翻译提供商的translate方法
  5. 结果处理：返回翻译结果或错误信息

故障转移机制 ​

javascript
async function translateWithFallback(texts, from, to, settings) {
  const { translationService, servicePriority, services } = settings;
  const errors = [];

  // 尝试主翻译服务
  try {
    const provider = getProvider(translationService, services[translationService]);
    return await provider.translate(texts, from, to);
  } catch (error) {
    errors.push({ provider: translationService, error });
    console.log(`主翻译服务 ${translationService} 失败: ${error.message}`);
  }

  // 按优先级尝试其他翻译服务
  for (const serviceName of servicePriority) {
    if (serviceName === translationService) continue;
    if (!services[serviceName]) continue;

    try {
      const provider = getProvider(serviceName, services[serviceName]);
      return await provider.translate(texts, from, to);
    } catch (error) {
      errors.push({ provider: serviceName, error });
      console.log(`翻译服务 ${serviceName} 失败: ${error.message}`);
    }
  }

  throw new AllProvidersFailedError(errors);
}

错误处理 ​

错误类型 ​

javascript
// lib/translation/providers/errors.js
class TranslationError extends Error {
  constructor(message, provider, originalError) {
    super(message);
    this.name = 'TranslationError';
    this.provider = provider;
    this.originalError = originalError;
  }
}

class ConfigurationError extends Error {
  constructor(message, provider, missingFields) {
    super(message);
    this.name = 'ConfigurationError';
    this.provider = provider;
    this.missingFields = missingFields;
  }
}

class AllProvidersFailedError extends Error {
  constructor(errors) {
    super('All translation providers failed');
    this.name = 'AllProvidersFailedError';
    this.errors = errors;
  }
}

错误处理流程 ​

  1. 翻译提供商错误：每个翻译提供商需要捕获API调用错误，并抛出标准化的错误
  2. 配置错误：检查配置是否完整，缺少必要字段时抛出配置错误
  3. 故障转移错误：当所有翻译服务都失败时，抛出综合错误

风险评估 ​

  1. API兼容性：不同翻译API的请求/响应格式可能不同，需要适配
  2. 错误处理：需要处理各种网络错误和API错误
  3. 性能影响：故障转移机制可能增加翻译延迟
  4. 配置复杂性：新的配置结构可能增加用户配置难度
